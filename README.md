# mathieuacher.com

Source of [mathieuacher.com](https://mathieuacher.com): a small static site generated by `build.py` from Markdown/TOML content and a BibTeX file, deployed to GitHub Pages.

## Everyday updates

| To change… | Edit |
|---|---|
| News | `content/news.toml` (newest first) |
| Publications | `data/acher.bib` (see below) |
| Bio | `content/about.md` |
| Research themes | `content/research.toml` |
| Software | `content/software.toml` |
| Teaching | `content/teaching.md` |
| PhD students, postdocs | `content/people.toml` (dates, status, theses.fr ids) |
| Research projects | `content/projects.toml` |
| Keynotes and invited talks | `content/talks.toml` |
| Juries | `content/juries.toml` |
| Outreach and media | `content/media.toml` |
| Committees, organization roles, reviewing | `content/service.toml` |
| PhD / HDR | `content/theses.toml` |
| Chess | `content/chess.md` |
| Name, title, affiliations, profiles, menu, llms.txt summary | `content/site.toml` |
| Look and feel | `templates/`, `static/css/site.css` |

Then preview and publish:

```sh
uv run build.py --serve     # http://localhost:8000
git commit -am "News: …" && git push   # GitHub Actions rebuilds and deploys
```

`uv` installs the two dependencies (Jinja2, Markdown) on the fly; Python 3.11+.

## Publications

`data/acher.bib` is the single source of truth. Each entry becomes an item on `/publications/` with its abstract, links, and a "cite" BibTeX. Fields the site understands beyond standard BibTeX:

- `abstract`: shown in an expandable panel and included in `publications.md` / `llms-full.txt`
- `award = {Best Paper Award}`: badge, listed under "Awards"
- `important = {1}`: shown in "Selected publications" on the home page
- `pdf`, `hal_id`, `doi`, `url`, `eprint` (+ `archiveprefix = {arXiv}`), `slides`, `youtube_id` (a URL), `twitter_id` (a URL), `code`, `artifact`: link chips
- `workshop = {1}`, `audience = {nationale}`, `other = {1}`, `sorte = {these}`: category (also used by the LaTeX CV scripts)

To find papers that are on DBLP / HAL / ORCID but not yet in the bib (stdlib Python, no install):

```sh
python3 tools/bibsync.py                  # list missing works
python3 tools/bibsync.py --add            # append them (metadata from DBLP, abstract/PDF from HAL, OpenAlex, Crossref)
python3 tools/bibsync.py --check          # validate the bib (braces, keys, required fields)
python3 tools/bibsync.py --check --sort   # also re-sort by date and normalize formatting
```

Works you deliberately leave out (preprints of published papers, datasets…) go in `tools/bibsync-ignore.txt` so they stop being reported. Review what `--add` wrote (keys, venue, `important`, `award`) before committing. Keys of existing entries must not change: they are URL anchors (`/publications/#key`, `/acher_bib.html#key`).

## Facts for CVs and application forms

The structured files above are the single source for public facts: the site, `llms.txt`, and dossiers (IUF, HCERES, RIPEC…) should all draw from them. Private details (supervision rates, budgets, contract notes) go in `../private/facts-private.toml`, outside this repository, never published.

```sh
python3 tools/facts.py check            # validate the files, compare with theses.fr, HAL award notes, and the bib
python3 tools/facts.py tables --lang fr # Markdown tables (theses, postdocs, projects, talks per period, juries),
                                        # merged with ../private/facts-private.toml when it exists
```

When a fact changes (new student, defense date, project end), change it here first, then regenerate the dossier tables.

## What gets generated

- `/`, `/publications/`, `/service/`: the human pages
- `/index.md`, `/publications.md`, `/service.md`: the same content as Markdown
- `/llms.txt` ([llmstxt.org](https://llmstxt.org) format) and `/llms-full.txt` (everything in one file, with abstracts)
- `/acher.bib`, `/acher_bib.html` (old URL, kept with the same anchors)
- schema.org JSON-LD (`Person` on every page, `ScholarlyArticle` list on `/publications/`), `sitemap.xml`, `robots.txt`
- `/services.html` redirects to `/service/`
- everything in `legacy/` is copied as-is so its old URLs keep working (today only the PhD manuscript, see below); folders without an `index.html` get a generated listing

## Hosting

GitHub Pages serves the site (workflow: `.github/workflows/pages.yml`, custom domain in `CNAME` via `content/site.toml`). The domain stays registered at OVH; its DNS points to GitHub:

| Host | Type | Value |
|---|---|---|
| `mathieuacher.com` | A | 185.199.108.153, 185.199.109.153, 185.199.110.153, 185.199.111.153 |
| `mathieuacher.com` | AAAA | 2606:50c0:8000::153, 2606:50c0:8001::153, 2606:50c0:8002::153, 2606:50c0:8003::153 |
| `www.mathieuacher.com` | CNAME | `acherm.github.io.` |
| `blog.mathieuacher.com` | CNAME | `acherm.github.io.` (unchanged) |

MX records (OVH mail) are not affected. The `_github-pages-challenge-acherm` TXT record verifies the domain on the GitHub account.

The primary address is `www.mathieuacher.com`; GitHub redirects `mathieuacher.com` to it. With the apex as primary, GitHub never started the HTTPS certificate request (stuck at "new" for more than a day in October 2026, despite valid DNS, a verified domain, re-adding the domain, and re-creating the Pages site); with `www` as primary, the request started. If you ever switch back, change the domain in the repository's Pages settings and `url`/`domain` in `content/site.toml` together.
